# 统一管理模型路径（AI_MODEL_ROOT）

`AI-config/` 下各 compose 文件用 `${AI_MODEL_ROOT}` 拼接模型挂载路径，方便在 Mac / 4090 Windows 工作站 / RTX-Pro-6000 / Ascend 服务器之间切换。

## 1. 准备 .env

模板见 `AI-config/.env.example`，根据机器实际情况复制并修改：

```bash
# Linux / Mac
cp AI-config/.env.example AI-config/.env

# 编辑 .env，例如：
# AI_MODEL_ROOT=/mnt/hdd/agent_resources/huggingface
# AI_HF_CACHE=/mnt/hdd/agent_resources/huggingface/_cache
```

Windows 工作站对应写法：
```env
AI_MODEL_ROOT=D:/dev_software/AI_models/huggingface
AI_HF_CACHE=D:/dev_software/AI_models/huggingface/_cache
```

> Compose 不会展开 `~`，必须用绝对路径或 `${HOME}`。

## 2. 加载方式

`docker compose` 默认只会从 **compose 文件所在目录** 找 `.env`。两种做法任选：

**方式 A（推荐）**：在 `AI-config/` 维护一份 `.env`，启动时显式指定：
```bash
cd AI-config/vllm-docker-compose
docker compose --env-file ../.env -f docker-compose-rtx-pro-6000_1.yml up -d
```

**方式 B**：每个子目录各放一份 `.env`（或软链接到 `AI-config/.env`）：
```bash
cd AI-config/vllm-docker-compose
ln -s ../.env .env
docker compose -f docker-compose-rtx-pro-6000_1.yml up -d
```

## 3. 子目录命名约定

宿主机的模型目录名与容器内 `/models/<name>` 保持一致最不容易出错。当前各 compose 假设的宿主子目录：

| 服务 | 宿主子目录（在 `${AI_MODEL_ROOT}` 下） |
| --- | --- |
| vllm Qwen3.6-35B-A3B-FP8 | `qwen36-35b-a3b-fp8` |
| vllm Qwen3-Embedding-4B | `qwen3-embedding-4b` |
| vllm Qwen3-30B-A3B-FP8 | `Qwen3-30B-A3B-FP8` |
| vllm Qwen3-30B-A3B-AWQ-4bit | `Qwen3-30B-A3B-AWQ-4bit` |
| vllm Qwen3-VL-8B-AWQ-4bit | `Qwen3-VL-8B-Instruct-AWQ-4bit` |
| whisper-asr | `faster-whisper-large-v3-turbo-ct2` |
| kokoro-zh-gpu | `Kokoro-82M-v1.1-zh` |
| llama-cpp-ascend | `qwen2.5-7b-fp16` |

> 把 `.env` 加进 `.gitignore`，只提交 `.env.example`。
